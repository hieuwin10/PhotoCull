Chạy các Model AI 30GB trên máy cá nhân

Cách tối ưu hóa RAM, GPU và cấu hình hệ thống khi chạy các model vision nặng (~30GB) qua Ollama trên phần cứng phổ thông.

⚠️ Thách thức

Model 30GB + 16GB RAM = Sập máy?

Không hẳn vậy. Với cấu hình đúng (mmap, pagefile, quantization), bạn có thể chạy các model lớn hơn cả RAM vật lý của mình. Điểm mấu chốt là hiểu rằng kích thước file ≠ dung lượng RAM cần thiết.

💾 Kỹ thuật 1: Ánh xạ bộ nhớ (Memory Mapping - mmap)

Các model GGUF sử dụng mmap — hệ điều hành sẽ ánh xạ file model trên đĩa vào không gian địa chỉ ảo. Chỉ những phần thực sự cần thiết cho việc suy luận (inference) mới được tải vào RAM vật lý.

⚡ BẮT BUỘC phải dùng SSD NVMe

HDD (~100 MB/s) so với SSD NVMe (~3.500 MB/s) = chênh lệch tốc độ 35 lần. Không có NVMe, việc suy luận sẽ chậm đến mức không thể chấp nhận được.

Kết quả: Một máy có 16GB RAM vẫn có thể chạy được model 30GB — nó sẽ chậm hơn so với máy có 32GB RAM, nhưng nó hoạt động được.

Giảm độ chính xác của model từ 16-bit xuống 4-bit để cắt giảm đáng kể nhu cầu bộ nhớ:

🪟 Kỹ thuật 3: Cấu hình Hệ thống Windows

3a. Tăng bộ nhớ ảo (Pagefile)

Khi hết RAM vật lý, Windows sẽ dùng pagefile trên đĩa cứng làm RAM tạm. Hãy đặt nó đủ lớn:

System Properties → Advanced → Performance Settings → Advanced → Virtual Memory
→ Bỏ tích "Automatically manage"
→ Chọn ổ đĩa SSD NVMe của bạn
→ Initial Size: 32768 MB (32GB)
→ Maximum Size: 65536 MB (64GB)
→ Khởi động lại máy

3b. Loại trừ khỏi Windows Defender

Defender sẽ quét file model 30GB mỗi khi tải — cực kỳ chậm:

Windows Security → Exclusions → Add Folder:
%USERPROFILE%\.ollama\models

3c. Đặt chế độ nguồn Hiệu suất cao (High Performance)

powercfg /setactive SCHEME_MIN

3d. Đóng các ứng dụng ngốn RAM

Trước khi chạy các model nặng, hãy đóng: Chrome (100-500MB/tab), VS Code (~1GB), Docker Desktop, v.v.

🎮 Kỹ thuật 4: Đẩy tải sang GPU (GPU Offloading) — Chia sẻ tải

Ollama sẽ tự động đẩy càng nhiều lớp (layers) của model sang GPU càng tốt tùy thuộc vào VRAM của bạn:

VRAM của bạnSố lớp trên GPUSố lớp trên CPUẢnh hưởng tốc độ
4 GB~12%~88%Cải thiện nhẹ
8 GB~25%~75%Nhanh hơn rõ rệt
12 GB~40%~60%Nhanh hơn nhiều
24 GB~80%~20%Gần như đạt tốc độ GPU tối đa
 
ollama ps     # Kiểm tra xem có bao nhiêu lớp đang nằm trên GPU
# Ép buộc sử dụng số lượng lớp GPU cụ thể:
set OLLAMA_GPU_LAYERS=20
📏 Kỹ thuật 5: Giảm cửa sổ ngữ cảnh (Context Window) — Tiết kiệm 5-15GB RAM

KV Cache tăng tuyến tính theo độ dài ngữ cảnh. Để phân tích ảnh, bạn hiếm khi cần quá 4096 token:

# Giảm từ mặc định 128K xuống 4K → tiết kiệm cực nhiều RAM
set OLLAMA_NUM_CTX=4096
ollama run llama3.2-vision

# Hoặc qua API:
{ "options": { "num_ctx": 4096 } }
💡 PhotoCull chỉ cần ngữ cảnh ~2K-4K

Các prompt phân tích ảnh thường ngắn. Một cửa sổ ngữ cảnh 4096 là quá đủ để phân tích một nhóm ảnh.

♻️ Kỹ thuật 6: Vòng đời Model — Tự động giải phóng (Auto-Unload)

Đừng giữ một model 30GB trong RAM khi người dùng không chủ động phân tích ảnh:

# Giải phóng model 5 phút sau lần sử dụng cuối (mặc định)
set OLLAMA_KEEP_ALIVE=5m

# Giải phóng ngay lập tức sau mỗi phản hồi
set OLLAMA_KEEP_ALIVE=0

# Chiến lược của PhotoCull:
# 1. Người dùng bấm "Analyze" → Tải model
# 2. Hoàn thành phân tích theo đợt → Giữ lại 5 phút
# 3. Không có yêu cầu mới → Tự động giải phóng → Giải phóng RAM
